# Интерфейс Verstak

Здесь описано, как устроен интерфейс: структура, оформление, адаптивность под
телефон. Правила рассчитаны на то, чтобы новый экран выглядел так же, как
существующие.

## Структура

```
packages/web/src
├── App.tsx              корень: подключение к серверу, вход, навигация
├── main.tsx             монтирование React и регистрация service worker
├── styles.css           дизайн-система (единственный файл стилей)
├── components/
│   ├── ModelPicker.tsx  выбиратель модели с поиском
│   └── QrCode.tsx       QR-код сопряжения
├── i18n/
│   ├── index.tsx        провайдер языка, подстановка параметров
│   └── messages.ts      словари ru/en
├── lib/
│   ├── api.ts           запросы к серверу, токен устройства
│   ├── download.ts      сохранение файла на телефон
│   ├── events.ts        подписка на поток событий OpenCode
│   ├── format.ts        время, числа, размеры, расписание
│   ├── icons.tsx        штриховые иконки
│   ├── qr.ts            сканирование кода камерой (только в приложении)
│   ├── server.ts        адрес сервера и определение среды
│   ├── theme.tsx        тема и переключатель
│   └── types.ts         типы данных API
└── views/               экраны: подключение, вход, проекты, сессия, задачи,
                         файлы, статистика, устройства, настройки
```

## Оформление

Все цвета, радиусы и тени — переменные CSS в начале `styles.css`. Прямые цвета
в компонентах не используются: тогда смена темы и правка палитры работают
сразу во всём интерфейсе.

Тема задаётся атрибутом `data-theme` на `<html>`:

| Значение | Поведение |
| --- | --- |
| `light` | Светлая тема |
| `dark` | Тёмная тема |
| атрибут отсутствует | Как в системе, через `@media (prefers-color-scheme: dark)` |

Переключатель темы (`ThemeToggle`) стоит в шапке боковой панели и меняет тему по
кругу; полный выбор из трёх вариантов — в «Настройках». Состояние живёт в
`ThemeProvider`, поэтому оба места показывают одно и то же.

Тема применяется маленьким синхронным скриптом в `index.html` до первой
отрисовки — иначе при тёмной теме первый кадр мелькал бы светлым.

### Токены

- `--surface-app`, `--surface-rail`, `--surface-card`, `--surface-inset` —
  слои поверхностей от фона к карточкам;
- `--text-primary`, `--text-secondary`, `--text-faint` — текст по важности;
- `--line-subtle`, `--line-default`, `--line-strong` — границы;
- `--accent`, `--accent-soft` — акцент и его заливка;
- `--success`, `--warning`, `--danger` — состояния и их мягкие заливки.

## Основные классы

| Класс | Назначение |
| --- | --- |
| `.app` | Каркас: боковая панель и основная область |
| `.sidebar`, `.nav`, `.list` | Боковая панель, навигация, списки |
| `.main`, `.content`, `.pad` | Основная область и её прокрутка |
| `.card` | Карточка с заголовком `.card-title` |
| `.btn`, `.icon-btn`, `.segmented` | Кнопки и переключатели |
| `.pill`, `.dot` | Статусы: готово, запускается, ошибка |
| `.thread`, `.message`, `.message-bubble` | Переписка |
| `.composer` | Поле ввода сообщения |
| `.banner` | Пояснение или ошибка во всю ширину |
| `.stat-grid`, `.stat` | Крупные числа в статистике |
| `.bars`, `.bar` | Столбики по дням |
| `.table` | Таблицы сводки |

Состояние в интерфейсе выражается классом, а не цветом в разметке: например,
точка состояния — `<span class="dot ready">`, метка — `<span class="pill error">`.

## Переписка

- Реплики пользователя выравниваются вправо и заливаются акцентом.
- Ответы ассистента — слева, на поверхности карточки.
- Вызовы инструментов идут отдельными строками с именем и состоянием.
- Разметка ответа разбирается функцией `renderRichText`: блоки кода, `код` в
  строке, **жирный**, *курсив*, ссылки. Этого достаточно для ответов OpenCode;
  полноценный markdown-движок здесь был бы лишним весом.
- Лента обновляется по потоку событий. Имена событий в API v2 не описаны как
  перечисление, поэтому вместо разбора каждого события лента перечитывается с
  задержкой 400 мс — так она остаётся верной при любых изменениях потока.
- Реплики пользователя запрашиваются отдельным запросом (`type=user`): OpenCode
  отдаёт последние сообщения по одной роли, и без этого собственные сообщения
  выпадали бы из окна.

## Телефон

Одна сборка работает и в браузере на компьютере, и как приложение на телефоне.

- При ширине до `860px` боковая панель и основная область занимают одну ячейку;
  какую показать, решает атрибут `data-mobile-view` (`rail` или `main`).
- Сверху появляются вкладки (`mobile-tabs`), они прокручиваются по горизонтали.
- Учитываются системные отступы через `env(safe-area-inset-*)` — «чёлка» и
  полоса жестов.
- `manifest.webmanifest` и `serviceWorker` (файл `public/sw.js`) позволяют
  добавить приложение на главный экран.

Service worker кэширует статику, но переходы между страницами всегда берёт из
сети. Иначе после обновления браузер получил бы старый `index.html` со ссылками
на уже удалённые файлы сборки, и экран остался бы пустым.

## Язык

Русский — язык по умолчанию. Словари лежат в `i18n/messages.ts`, тип ключей
выводится из русского словаря, поэтому забытый перевод в английском — ошибка
типов, а не пустая строка на экране. Сервер отдаёт свою локаль в
`/api/auth/status`; она применяется, только если пользователь ещё не выбирал
язык вручную.

## Доступность

- Видимый фокус у всех элементов (`:focus-visible`).
- Кнопки без подписи получают `aria-label`, текущий пункт — `aria-current`.
- Анимации отключаются при `prefers-reduced-motion: reduce`.
- Цвет не единственный носитель смысла: состояния подписаны словами.
